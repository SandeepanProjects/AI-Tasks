# 5. What should you say in your interview?

"We supported two input scenarios in the compliance platform.

The first was query-based RAG, where a compliance officer could ask a natural-language question. We generated query embeddings, retrieved relevant policy chunks from PostgreSQL using pgvector, and passed the retrieved context to the LLM to generate an evidence-based response.

The second was document-based compliance review. An advisor could upload a financial document. We extracted its text, identified individual financial claims, used those claims as retrieval queries against the same compliance policy knowledge base, and analyzed them against the retrieved policies.

Both approaches shared the same RAG retrieval layer and compliance analysis components, while LangGraph orchestrated the workflow based on the input type."

One important architectural distinction: We are retrieving compliance policies, not retrieving answers from previously uploaded advisor documents. The advisor's document is the material being evaluated; the policy knowledge base is the source of compliance rules.

That distinction is particularly important in a financial compliance interview.
